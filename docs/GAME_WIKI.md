# Caleb's Arcade - game wiki (hub)

> "The front door for every browser game Caleb has shipped: 112 games, no ads, no accounts, no installs."
> (README.txt). A static portal: a tile mosaic (`index.html`) and one play page per game (`play.html?g=<id>`)
> that loads the game in an iframe. 43 games live in this repo (35 cabinet folders + 8 Godot web builds);
> 69 are hosted by the owner's other Pages sites and only linked (arcade-hub 37, neon-game-arcade 25,
> playables 6, bloxburg-town 1; counts from `catalog.js`).

## How to play (the portal)
| Action | Desktop | Touch | Evidence |
| --- | --- | --- | --- |
| Find a game | tiles, category rail, search (`/`), `S` random game, `1`-`9` jump to a card | tiles, category chips, search | README.txt "Shortcuts"; `assets/site.js:246` |
| Start a game | `Play` on the splash, or `P` | `Play` (goes straight to fullscreen / theatre on phones) | `start()` `assets/site.js:555-567` |
| In a game (SDK games) | `P` pause, `M` mute, `H` how to play | round buttons | `assets/site.js:674-678` |
| Restart / next / like / fullscreen | `R` / `N` / `L` / `F` | toolbar | `restart()` `assets/site.js:629` |
| Leave | back to the shelf, or "Up next" | same | play page rails |
Tab-away pauses every SDK game (`visibilitychange` -> `toGame('pause')`, `assets/site.js:673`).

## Core loop (the portal)
Browse a row (Continue playing, Because you played, Favourites, New, Popular, one row per category), open a
game's page (art splash, how-to steps, controls table and tips from `qa/standard/meta/<id>.json`, your best
and play count), press Play, play inside the frame, then take "Up next" or go back. Every minute played,
first plays, new categories, finished rounds and daily streak days feed the profile.

## Structure (screens and states)
`index.html` (views `./?cat=<id>`, `./?view=new|popular|recent|favourites|all|iphone|trophies`,
`./?q=<words>`) -> `play.html?g=<id>` (splash -> loading cover -> iframe; `started` flag in
`assets/site.js:554`) -> back / next. Settings sheet (gear or `,`): theme, accent, tile size, motion, names,
default stage size, external games in a new tab, "Your data" export / import / clear, tester report. The SDK
(`assets/arcade-sdk.js`) adds a pause sheet (resume, how to play, sound, codes, restart, exit) to every game
that loads it. `catalog.js`, `assets/game-meta.json`, `sitemap.xml` and counts are generated by
`tools/build_catalog.py` (do not hand-edit).

## Progression (the portal)
- Profile (`assets/profile-core.js:3-30`): XP and level (max 50), stars, a daily streak with a rest day,
  three daily quests (17 quest kinds in `QUESTS`), 57 badges (`ACH.length` is 57 when the module is loaded in
  node), cosmetics; fed only by SDK reports and play time. "No currency to spend ...
  XP and stars only ever go up, and they never unlock anything but looks" (profile-core.js:24-26), so it does
  not change the next run of any game.
- Per game: the play page shows "Your best" and "You played N times" (`facts()`, `assets/site.js:543-551`).
- In-run ramps and unlocks belong to each game; see the table and the four pages.

## Win / lose / fail
None at hub level. Each game owns its end states; the play page's `R` reloads the frame
(`assets/site.js:629`), which for games without an in-place restart doubles as "exit to title".

## Scoring and economy
Hub level: none beyond XP/stars (above). Per game: see the four pages.

## Every game, 20 seconds each
One row per catalog game, in `catalog.js` order. Column sources, so nobody mistakes a claim for a test:

- **What you do / Controls / Loop**: authored text from `assets/game-meta.json` (built from
  `qa/standard/meta/<id>.json`); not re-verified per game in this pass.
- **Progression**: the P-grade from the last progression run (`qa/health-results/progression/progression.md`,
  generated 2026-09-30, 107 games; not re-run in this pass). P0 nothing persists, P1 only a best score, P2 progress
  persists plus one system, P3 a sink fed by two or more sources.
- **Juice**: a static scan of the code (`scan.audio` and `scan.render` in `assets/game-meta.json`): whether the code
  plays audio, and how it renders. It does not say the feedback is good.
- **20 s run**: this session's `node qa/harness/play.mjs --sweep --secs 20` (desktop 1280x720, generic random policy,
  through the portal): page errors, how it started (`reached play` = the game posted the SDK scene `play`;
  `screen changed` = visible text changed), fps on SwiftShader under the box load quoted in Stability.
- **Triage**: a rule, not a rubric verdict, for the games without a full page. `FIX` = a page error, NaN/undefined on
  screen or a load that never finished in the 20 s run; `RETHINK candidate` = P0 in the progression report (nothing
  persists; with no in-run ramp that is the rubric's Progression <= 1, which a smoke run cannot settle); `unscored` = no defect seen in a smoke run, which is not a pass. The four profiled games
  show their full-page verdict.

## Harness: what it does and how to run it
`qa/harness/play.mjs` (Playwright, Chromium on SwiftShader; it starts its own static server for the repo and
routes `https://calebhomwe.github.io/<repo>/...` to a clone next to this repo when one exists, else to the live
site, `play.mjs:243-250`).

- **Sweep** (`--sweep [--local] [--only ids] [--secs 20] [--mode mobile]`): for every catalog game, a fresh
  browser context opens `play.html?g=<id>`, presses the portal's Play, waits for the frame, then starts the
  game with the `start` hint in `assets/game-meta.json` (a selector or `key:Space`) and up to two visible
  Play-like buttons (`PLAYISH`, `play.mjs:489`), else a centre click. For `--secs` it then acts every 150 ms:
  a random key (arrows, Space, WASD, Enter; 60-200 ms hold), a click in the middle 70% of the frame half the
  time, a drag 30% of the time, and every eighth tick a click on any visible button (taps and touch drags in
  `mobile`). Recorded per game: load time, how it started, the SDK scenes it posted (`title` / `play` /
  `over`), whether visible text changed, page errors, console errors, failed requests, NaN / undefined /
  `[object Object]` / Infinity in the visible text, fps, canvases. Verdict: `error` (page error), `bad-text`,
  `blocked` (did not load before the deadline), `ok` (posted `play` or the screen text changed), `no-start`.
  Exit 1 on any `error`, `bad-text` or `blocked`. This is a smoke run with a random policy: `ok` means "loads,
  starts and survives 20 s of input", not "good".
- **One game** (`--game <id> --mode default|mobile|storm|resize|blur|storage-blocked|long [--episodes n]
  [--secs s] [--fault name]`): plays episodes with that game's own policy (below), checks every tick that
  every state field is a finite number or a string, within bounds, and that phase changes are legal; fails on
  a page error, a stuck run (playing but no state change for 15-20 s), no progression signal moving in an
  episode, a restart that does not reach play, NaN/undefined text on screen at the end, or heap growth in
  `long`. The start press waits for the game's readiness predicate and is repeated (up to 3 presses, the third a
  DOM click on the control) if the run has not begun 4 s later; the press count is in each report. A paused game
  (its own pause, or the arcade SDK's sheet) is resumed the way a player would. Modes: `mobile` 390x844 touch with a
  touch policy; `storm` adds two random inputs per tick; `resize` flips between 1280x720 and 390x844 every
  5 s; `blur` fires blur / visibilitychange and focus every 5 s in the portal and the game frame;
  `storage-blocked` makes `localStorage` and `sessionStorage` throw `SecurityError` in every frame; `long`
  samples the JS heap every 10 s.
